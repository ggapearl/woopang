# PDNOM 작업 성향 가이드

> AI 어시스턴트가 pdnom과 효율적으로 협업하기 위한 성향 분석 문서
> 어떤 프로젝트에서든 이 문서를 참고하여 프롬프트 작성 및 결과물 방향을 설정할 것

---

## 1. 핵심 성향 요약

| 영역 | 성향 |
|------|------|
| 완성도 | 기능 작동 < 시각적/경험적 완성도 |
| 디테일 | 매우 꼼꼼함, 엣지 케이스 중시 |
| 속도 | 빠른 것보다 부드럽고 자연스러운 것 |
| 강도 | 과하지 않고 은은하게 |
| 피드백 | 직접적, 구체적, 다중 이슈 동시 제기 |
| 코드 | 재사용 가능한 구조, 명확한 주석 |

---

## 2. 프롬프트 작성 패턴

### 2.1 요청 방식
```
특징:
- 여러 요구사항을 한 번에 나열
- 스크린샷/이미지와 함께 구체적 문제 설명
- "확인해서 수정해줘" 형태의 직접적 요청
- 문제점과 기대 결과를 동시에 언급
```

### 2.2 예시 패턴
```
"[A]가 [B]해야 하는데 안되거든? 확인해서 수정해주고..
[C]에 있어서는 [D] 효과가 없는데 확인해서 [E]하도록 해주고..
[F]도 너무 [G]하니까 [H]하게 해줘."
```

### 2.3 AI가 인식해야 할 키워드
| 키워드 | 의미 |
|--------|------|
| "확인해서" | 원인 파악 후 수정 요청 |
| "당최", "여전히" | 이전 시도가 실패했거나 미해결 |
| "~하도록 해줘" | 구체적인 결과물 기대 |
| "잘 확인해서" | 꼼꼼한 검토 필요 |
| "너무 ~하니까" | 현재 상태가 과함, 조절 필요 |

## 3. 품질 기준

### 3.1 완성도 우선순위
```
1순위: 모든 상황에서 정상 작동 (엣지 케이스 포함)
2순위: 시각적으로 자연스럽고 부드러움
3순위: 사용자가 직관적으로 이해 가능
4순위: 코드의 재사용성/확장성
```

### 3.2 "작동한다"의 정의
```
❌ 잘못된 기준: 특정 조건에서 기능이 실행됨
✅ 올바른 기준: 어떤 각도/상황/디바이스에서도 의도대로 작동
```

### 3.3 테스트 체크포인트
- [ ] 모든 방향/각도에서 인터랙션이 정상 작동하는가?
- [ ] 모바일/데스크톱 모두 대응되는가?
- [ ] 빠른 연속 동작에도 깨지지 않는가?
- [ ] 예외 상황에서 graceful하게 처리되는가?

## 4. 디자인 선호도

### 4.1 일반 원칙
```
- 과하지 않은 것 > 화려한 것
- 느리고 부드러운 것 > 빠르고 역동적인 것
- 은은한 효과 > 강렬한 효과
- 고급스럽고 프리미엄한 느낌 선호
```

### 4.2 애니메이션 속도 기준
| 유형 | 선호 속도 |
|------|-----------|
| 호버 효과 | 0.2s ~ 0.4s |
| 페이드 인/아웃 | 1s ~ 5s (느리게) |
| 반복 애니메이션 | 10s ~ 25s 주기 |
| 배경 요소 움직임 | 매우 느리게 |
| 사운드 볼륨 | -12dB 이하 (조용하게) |

### 4.3 시각적 효과 선호도
```
선호:
✅ 글로우/빛 번짐 효과
✅ 그라데이션 배경
✅ 부드러운 그림자
✅ 미묘한 패럴랙스
✅ 호버 시 자연스러운 확대/강조

비선호:
❌ 급격한 색상 변화
❌ 과도한 바운스 효과
❌ 시끄러운 알림음
❌ 번쩍이는 효과
```

### 4.4 UI 패턴 선호
```
버튼: 투명 배경 + 테두리 → 호버 시 채워지는 효과
카드: 미묘한 배경 그라데이션 + 글로우
입력: 심플한 테두리 + 포커스 시 강조
모달: 어두운 오버레이 + 중앙 팝업 + 스케일 애니메이션
```

## 5. 인터랙션 설계

### 5.1 핵심 원칙
```
"시각적으로 보이는 대로 작동해야 한다"

- 클릭 가능해 보이면 클릭 가능해야 함
- 3D 오브젝트는 모든 각도에서 터치 가능해야 함
- 호버 영역 = 시각적 영역
```

### 5.2 마우스/터치 반응
```
필수 구현:
- 마우스 움직임에 따른 미묘한 반응 (패럴랙스 등)
- 호버 시 시각적 피드백
- 클릭/터치 시 즉각적인 피드백
- 드래그 가능 요소는 커서 변경 (grab → grabbing)
```

### 5.3 피드백 타이밍
```
즉시 (0-100ms): 클릭/터치 피드백
짧게 (100-300ms): 호버 상태 변화
보통 (300ms-1s): 상태 전환
길게 (1-5s): 로딩, 페이드 인/아웃
```

## 6. 코드 작성 스타일

### 6.1 구조 선호도
```
- 재사용 가능한 클래스/컴포넌트 구조
- 설정값은 상단에 상수로 분리
- 관련 기능끼리 그룹핑
- 명확한 섹션 구분 주석
```

### 6.2 주석 스타일
```javascript
// ============================================================
// 섹션 제목 - 영어/한국어 병행
// ============================================================

// 간단한 설명 (한국어 가능)
const value = 123; // 인라인 주석
```

### 6.3 설정값 분리 패턴
```javascript
// 설정값을 상단에 모아두기
const CONFIG = {
    animationDuration: 2000,
    fadeInTime: 3,
    maxItems: 50,
    volume: 0.15  // -12dB 이하
};
```

### 6.4 에러 처리
```javascript
// 조용한 실패 처리 선호 (사용자에게 불필요한 에러 노출 지양)
try {
    riskyOperation();
} catch(e) {
    console.warn('처리 실패:', e);
    // fallback 동작
}
```

## 7. 반응형 설계

### 7.1 브레이크포인트 기준
```
데스크톱: > 1000px (풀 기능)
태블릿: 768px ~ 1000px (기능 축소)
모바일: < 768px (핵심 기능만)
소형 모바일: < 480px (최소 UI)
```

### 7.2 모바일 대응 원칙
```
- 3D/복잡한 효과는 단순화 또는 제거
- 슬라이드 네비게이션 → 스크롤 모드로 전환
- 터치 영역 충분히 확보 (최소 44px)
- 고정 헤더로 네비게이션 제공
```

## 8. 피드백 대응 가이드

### 8.1 피드백 유형별 대응
| 피드백 | 의미 | 대응 |
|--------|------|------|
| "안되거든?" | 기능 미작동 | 원인 파악 후 근본적 수정 |
| "확인해서" | 검토 필요 | 관련 코드 전체 점검 |
| "여전히" | 이전 수정 실패 | 다른 접근법 시도 |
| "너무 ~해" | 과함 | 값 축소/조절 |
| "없는데" | 누락 | 해당 기능 추가 |
| "이상하게" | 버그 | 디버깅 후 수정 |

### 8.2 수정 후 응답 형식
```
1. 무엇을 수정했는지 명확히 설명
2. 변경된 값/로직 요약
3. 추가로 개선한 점 언급
4. 필요시 테스트 방법 안내
```
