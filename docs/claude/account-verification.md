# 정산계좌 검증 설계 (농민.com)

> 계좌 관련 코드를 건드릴 때 반드시 먼저 읽을 것. 2026-09-04 작성.

## 1. 왜 중요한가 — 돈이 직접 오간다

농민.com 은 **무통장입금 직거래** 구조다. 구매자에게 보여주는 계좌는
플랫폼 계좌가 아니라 **판매자 본인 계좌**(`nongmin_sellers.bank_account`)다.

```
구매자 ──(직접 이체)──> 판매자 통장
```

주문 조회 쿼리(`nongmin_server.py` 의 `SELECT ... s.bank_name, s.bank_account, s.bank_holder`)가
그대로 `order_complete.html` · `account_orders.html` 에 뿌려진다.

**따라서 계좌번호가 한 자리만 틀려도 생판 남의 통장으로 돈이 들어간다.**
은행 실무상 수취인이 반환에 동의하지 않으면 되돌리기 매우 어렵다.
→ 판매자 정산 편의 문제가 아니라 **구매자 금전사고** 문제다.

## 2. 현재 구현 (0단계 — 2026-09-04 완료)

PG 계약·비용 없이 할 수 있는 방어를 먼저 넣었다.

| 방어 | 구현 위치 |
|---|---|
| 은행 **목록 선택만** 허용 (자유입력 금지) | `BANKS` 상수, `banks` 컨텍스트 |
| 은행 **표준코드** 저장 | `nongmin_sellers.bank_code` (VARCHAR 4) |
| 계좌번호 **숫자만** 저장 ('-'·공백 제거) | `normalize_account()` |
| 계좌번호 **자릿수** 검증 | `normalize_account()` (은행별 min/max) |
| 계좌번호 **2회 입력 대조** | `seller_account.html` (변경 시에만 노출) |
| **경고 문구** ("구매자가 직접 입금") | `seller_account.html` |

### 핵심 함수
```python
normalize_account(bank_name, account)
  -> (bank_name, bank_code, account_digits, error_or_None)
```
가입(`/seller/register`)·수정(`/seller/account/update`) 양쪽에서 호출한다.
실패 시 수정은 `?m=bank_bad`, 가입은 `error=` 로 되돌린다.

### ⚠ 지키기
- **은행 목록을 템플릿에 하드코딩하지 말 것.** 예전에 `seller_auth.html` 안에
  이름만 든 배열이 박혀 있었고, 정보수정 화면은 자유 텍스트라 서로 어긋났다.
  지금은 `BANKS` 가 유일한 소스이고 `inject_base()` 가 `banks` 로 내려준다.
- **자릿수 범위는 넉넉하게.** 은행별 예외 계좌가 많아 좁게 잡으면 정상 판매자를 막는다.
  오타는 자릿수가 아니라 **2회 입력 대조**로 잡는 게 맞다.
- **예금주명 ≠ 판매자명 을 오류로 처리하지 말 것.** 농가는 가족 명의 계좌를 흔히 쓴다.
  (실제 사례: 판매자 김영춘 / 예금주 이구순 — 정상)

## 3. 다음 단계 (1단계 — 미구현, 비용 발생)

0단계는 **오타**를 막을 뿐 **계좌 실존·소유**는 증명하지 못한다.
실제 검증은 외부 API 가 필요하고 건당 과금된다.

| 방식 | 무엇을 보장 | 경로 | 비고 |
|---|---|---|---|
| **계좌 실명조회** | 계좌 존재 + 예금주명 | PG사(토스페이먼츠·나이스·포트원 등) 부가서비스 | 건당 과금. 오타는 잡지만 **소유 증명 아님** |
| **1원 인증** | 계좌 존재 + **본인 소유** | 동일 PG사 / 오픈뱅킹 | 더 강력. 입금자명에 코드를 넣어 본인 앱에서 확인 |
| 오픈뱅킹 직접 | 위 전부 | 금융결제원 이용기관 등록 | 심사 있고 무겁다. 규모 커지면 검토 |

### 붙일 때 설계
1. `nongmin_sellers` 에 `bank_verified BOOLEAN`, `bank_verified_at TIMESTAMP` 추가
2. 계좌 저장 시 검증 API 호출 → 예금주명 대조 결과를 **참고용으로 보여주되**
   본인명과 달라도 **차단하지 않는다**(2번 항목의 가족명의 사유)
3. `bank_verified = FALSE` 인 판매자는 **상품 노출 차단** 또는 주문 시 경고
4. 은행코드는 이미 `bank_code` 에 있으니 그대로 API 파라미터로 쓴다

## 4. 참고
- 정부·공공 사이트의 `계좌확인` 버튼이 위 "계좌 실명조회"다.
- 검증 없이 운영하는 동안에는 **판매자가 계좌를 바꿀 때마다 2회 입력**을 강제하는
  현재 방식이 사실상 유일한 방어선이다. 이 로직을 약화시키지 말 것.
